# Reglet v1 implementation plan

Design spec: `docs/specs/2026-07-10-reglet-v1-design.md`. Read that for product context.

## Global constraints (apply to every task)

- TypeScript strict; **never `any`**. Bun runtime; `bun test` for tests; ESM only.
- Monorepo: `packages/core` (no CLI/IO-side-effect imports at module top level), `packages/cli` (bin `reglet`), `packages/server`.
- All home-dir access goes through `regletHome()` / `providerHome()` helpers that respect `REGLET_HOME` and `REGLET_PROVIDER_HOME` env overrides so tests run in a sandbox temp dir. Tests must NEVER touch the real `$HOME`.
- Every file write of a generated output goes through one writer utility that (1) creates a first-time backup, (2) records the output hash in the manifest.
- Cross-platform: no hardcoded `/`; use `node:path`. Windows support matters (paths, no symlinks, no POSIX-only APIs except in launchd-specific code).
- Reference (read-only) for provider format details: the ruler checkout at `/Users/elijah/conductor/workspaces/ruler/sofia` — esp. `src/agents/*.ts`, `src/mcp/`, `src/core/hash.ts`.
- Commit style: conventional commits (`feat: …`, `test: …`). Run `bun run typecheck` and `bun test` before reporting DONE.

## Canonical data model

Master dir `~/.reglet/` (override: `REGLET_HOME`):

```
rules/*.md                 # concatenated in filename sort order into provider rules files
skills/<name>/SKILL.md     # + arbitrary asset files per skill dir
mcp/servers.json           # {"mcpServers": {"<name>": {"command": "...", "args": [], "env": {}, "url": "..."}}}
reglet.toml                # config (below)
.state/manifest.json       # applied-output record (below); never synced
.state/backups/<provider>/<ISO-timestamp>/<original filename>
.state/drift.json          # queued drift events
.state/sync.json           # server url, device token, cursor; chmod 600
.state/sync-base/          # shadow copies of last-synced versions (3-way merge base)
```

`reglet.toml`:

```toml
[providers.claude]
enabled = true
rules = true      # false = unenrolled from that content type
skills = true
mcp = true
# (same table per provider: codex, cursor, gemini, windsurf, opencode)

[sync]
server_url = ""
```

`manifest.json`: `{ "version": 1, "outputs": { "<abs output path>": { "provider": "claude", "content": "rules|skills|mcp", "hash": "sha256hex", "appliedAt": "ISO", "backedUpTo": "<path>|null", "managedKeys": ["serverA"] } } }` — `managedKeys` only for merged JSON/TOML files (which MCP server entries reglet owns).

## Provider registry (paths verified on a real machine 2026-07-10)

| provider | rules output | skills dir | mcp output & format |
|---|---|---|---|
| claude   | `~/.claude/CLAUDE.md` | `~/.claude/skills/<name>/` | merge `mcpServers` key inside `~/.claude.json` (large JSON with many unrelated keys — preserve everything else byte-stable where possible) |
| codex    | `~/.codex/AGENTS.md` | `~/.agents/skills/<name>/` | `[mcp_servers.<name>]` tables in `~/.codex/config.toml` (TOML merge, preserve all other content incl. comments — use a TOML lib that round-trips, or document lossiness) |
| cursor   | *(unsupported in v1 — Cursor global rules live in app settings; registry entry has `rules: null` and docs note)* | `~/.cursor/skills/<name>/` | `~/.cursor/mcp.json` (`mcpServers` key) |
| gemini   | `~/.gemini/GEMINI.md` | `~/.gemini/skills/<name>/` | `~/.gemini/settings.json` (`mcpServers` key, preserve other keys) |
| windsurf | `~/.codeium/windsurf/memories/global_rules.md` | *(unsupported v1)* | `~/.codeium/windsurf/mcp_config.json` (`mcpServers`) |
| opencode | `~/.config/opencode/AGENTS.md` | `~/.config/opencode/skills/<name>/` | `~/.config/opencode/opencode.json` (`mcp` key; opencode format: `{"<name>": {"type": "local", "command": ["cmd", ...args], "environment": {}}}` or `{"type": "remote", "url": ...}` — see ruler `src/agents/OpenCodeAgent.ts`) |

Rules outputs are **whole-file** writes prefixed by the generated header:

```markdown
<!-- ⚠️ GENERATED BY REGLET — DO NOT EDIT THIS FILE DIRECTLY.
Source of truth: ~/.reglet/rules/  (edit those files, then `reglet apply`, or let the daemon do it)
Agents: if you need to change these instructions or add new ones, edit the files in
~/.reglet/rules/ instead of this file. To stop reglet from managing this file, run:
  reglet unenroll <provider>:rules
Hand-edits here will be detected as drift and you'll be prompted to import or discard them. -->
```

(`<provider>` interpolated. Header is a constant in core, exported, used verbatim by drift detection to strip before import.)

### Task 2: Core foundation — paths, config, master-dir model

In `packages/core`:
- `paths.ts`: `regletHome()` (`REGLET_HOME` ?? `~/.reglet`), `providerHome()` (`REGLET_PROVIDER_HOME` ?? `os.homedir()`) — every provider path is built from `providerHome()`.
- `config.ts`: load/save `reglet.toml` (use `smol-toml`). Typed `RegletConfig` with defaults (all six providers present, enabled=false until init enrolls them). Missing file → defaults.
- `master.ts`: `loadMasterDir()` → `{ rules: {relPath, content}[] (sorted), skills: {name, files: {relPath, absPath}[]}[], mcpServers: Record<string, McpServerDef> }`. `initMasterDir()` creates the skeleton (dirs + empty servers.json + default reglet.toml + starter `rules/00-general.md` with a short comment).
- `manifest.ts`: typed load/save of `.state/manifest.json`, `recordOutput()`, `getOutput()`.
- `fsutil.ts`: `writeFileEnsuringDir`, `sha256File`, `sha256String`, `copyDirRecursive`.
- `index.ts` exports.
- Tests (`packages/core/test/`): config round-trip, master-dir loading from a fixture tree under a temp `REGLET_HOME`, manifest round-trip, init idempotency.

### Task 3: Provider registry + rules engine + apply

In `packages/core`:
- `providers/types.ts`: `ProviderId` union (`'claude'|'codex'|'cursor'|'gemini'|'windsurf'|'opencode'`), `ProviderAdapter` interface: `{ id, displayName, detect(): Promise<boolean>, rulesPath(): string | null, skillsDir(): string | null, applyMcp(servers, ctx): Promise<ApplyResult> | null-capable, inventory(): Promise<ProviderInventory> }` — design the exact interface; keep one file per provider in `providers/`.
- `providers/registry.ts`: `getAdapter(id)`, `allAdapters()`.
- `header.ts`: the generated header constant (see above) + `renderRulesFile(provider, ruleFiles)` = header + concatenated rule file contents separated by `\n\n---\n\n` with `<!-- source: rules/<relPath> -->` markers.
- `engine/apply.ts`: `applyAll(opts: {providers?: ProviderId[], contents?: ('rules'|'skills'|'mcp')[], dryRun?: boolean})`:
  - respects `enabled` + per-content enrollment from config,
  - rules: whole-file write via the safe writer (backup-once + manifest),
  - skills: for each master skill, copy dir into provider skills dir under the skill's name; remove previously-managed skills that no longer exist in master (track via manifest); never touch non-reglet skills,
  - mcp: this task ships the engine calling `adapter.applyMcp` but only the **claude** and **gemini** JSON-merge implementations (rest in Task 4),
  - returns structured `ApplyReport` (written/skipped/unchanged per output).
- Safe writer `engine/writer.ts`: first-time backup to `.state/backups/<provider>/<timestamp>/`, write, hash into manifest. Unchanged content (hash equal) = skip, no backup.
- Detection (`detect()`): provider dir exists (e.g. `~/.claude`, `~/.codex`, …).
- Tests: golden-file tests per provider for rules output; apply skips unenrolled; backup created exactly once; unchanged apply is a no-op; skills add/update/remove lifecycle in temp sandbox.

### Task 4: MCP converters for codex (TOML), cursor, windsurf, opencode + managed-keys semantics

- Codex: parse `~/.codex/config.toml`, upsert `[mcp_servers.<name>]` tables (`command`, `args`, `env`), preserve unrelated content. Use `smol-toml` (documented caveat: comments are not preserved — record original file in backup, note in docs) — check ruler `src/agents/CodexCliAgent.ts` + `src/mcp/` for field mapping.
- Cursor `~/.cursor/mcp.json`, windsurf `mcp_config.json`: standard `mcpServers` merge (create file if absent).
- OpenCode `opencode.json`: transform to opencode's `mcp` schema (local: `command` array = `[command, ...args]`, `environment`; remote: `url`).
- Managed-keys semantics everywhere (incl. claude/gemini from Task 3 — refactor if needed): reglet only adds/updates/removes server entries listed in `manifest.outputs[path].managedKeys`; user-added servers in the same file are never touched; a server removed from master is removed from the provider file on next apply.
- Tests: golden merges incl. pre-existing user servers, removal lifecycle, codex TOML round-trip preserving unrelated tables.

### Task 5: Drift detection, revert, restore, import

- `engine/drift.ts`: `detectDrift()` — for each manifest output, compare current file hash vs recorded; classify `missing | modified | clean`. For merged files (mcp), drift = managed subtree differs from what master would produce.
- `engine/import.ts`: for a drifted **rules** output: strip header, and (v1) write the drifted content to `rules/imported-<provider>-<date>.md` after removing the concatenation of known sources if identical prefix — keep simple: save full stripped content, print instructions. For skills: copy changed skill back into master. For merged mcp: report only (no auto-import).
- `engine/revert.ts`: `revert(provider?)` — restore every backed-up original, delete reglet-created files that had no original, prune manifest entries.
- `restore` = alias of revert per provider (same engine).
- `.state/drift.json` queue helpers (append event, list, clear) for the daemon.
- Tests: drift detect on hand-edited file; import produces master file with stripped header; revert restores byte-identical originals and removes created files.

### Task 6: CLI — init, scan/import onboarding, apply, status, diff, unenroll, restore, revert

In `packages/cli` (use `commander` + `@clack/prompts`, thin layer over core):
- `reglet init`: scan (adapters' `detect()` + `inventory()`: existing rules files, skills, mcp servers per provider) → multi-select providers to enroll → multi-select what to import into master (rules → `rules/imported-<provider>.md` stripped of nothing (originals aren't reglet-generated), skills copied, mcp servers merged into `mcp/servers.json` with name-collision prompt) → confirm summary → backups + first `apply`. `--yes` non-interactive mode (enroll all detected, import all) for tests/scripts.
- `reglet scan`: print detection/inventory table without changing anything.
- `reglet apply [--provider p] [--dry-run]`, `reglet status` (enrollment, drift, last apply, sync state), `reglet diff` (unified diff of what apply would change), `reglet unenroll <provider>[:<rules|skills|mcp>]` (+ `enroll`), `reglet restore [provider]`, `reglet revert`.
- Exit codes: 0 ok, 1 error, 2 drift-found (for status --check).
- E2E tests driving the CLI with `REGLET_HOME`/`REGLET_PROVIDER_HOME` pointed at temp dirs (use `--yes`; assert files land in fake `~/.claude` etc.).

### Task 7: Daemon + service install

In `packages/cli`:
- `reglet daemon run`: chokidar watch on master dir (rules/skills/mcp/reglet.toml) → debounce 500ms → `applyAll()` (+ `sync push` if configured, after Task 9 — call through a no-op hook for now); watch enrolled provider outputs → on change not caused by own apply (compare hash to manifest) append drift event + `console.log`; on macOS also `osascript -e 'display notification …'` (best-effort, try/catch).
- `daemon start/stop/status`: detached spawn with pidfile in `.state/daemon.pid`; logs to `.state/daemon.log`.
- `daemon install/uninstall`: macOS launchd plist `~/Library/LaunchAgents/com.reglet.daemon.plist` (RunAtLoad, KeepAlive) + `launchctl load/unload`; Windows `schtasks /create /sc onlogon`. Guard by `process.platform`.
- Tests: watcher-triggered apply in sandbox (touch master rule file → provider file regenerates); drift event queued when provider file edited externally. Service install covered by unit-testing the generated plist/schtasks command string, not by actually installing in tests.

### Task 8: Sync server

In `packages/server` (Bun + Hono + `bun:sqlite`):
- Modes: multi-user (email+password, scrypt hashes) or single-user (`REGLET_TOKEN` env — no signup). SQLite path via `REGLET_DB` (default `./reglet.sqlite`).
- Schema: `users(id,email,pass_hash)`, `devices(id,user_id,name,token_hash,created_at)`, `files(user_id,path,revision,hash,content BLOB,deleted,seq)`, `file_history(user_id,path,revision,hash,content,created_at)`, global per-user monotonic `seq`.
- REST (JSON; auth: `Authorization: Bearer <device token>`):
  - `POST /v1/auth/register`, `POST /v1/auth/login` → short-lived session token
  - `POST /v1/pair/start` (session) → `{code}` (6 chars, 10 min TTL); `POST /v1/pair/claim {code, deviceName}` → `{deviceToken}`
  - `GET /v1/changes?since=<seq>` → `{changes: [{path, revision, hash, deleted, seq}], cursor}`
  - `GET /v1/files/:path` → `{revision, hash, contentBase64}`
  - `PUT /v1/files/:path` body `{baseRevision, contentBase64}` → `{revision}`; `409 {headRevision, contentBase64}` when baseRevision ≠ head
  - `DELETE /v1/files/:path {baseRevision}` → tombstone
  - `GET /healthz`
- Minimal HTML page at `/` (server info + pairing approval is CLI-driven, page just documents endpoints).
- `Dockerfile` (oven/bun, single stage ok) + `docs/self-hosting.md` (docker run + env vars).
- Tests: full API flow via `app.request()` (register→login→pair→put→changes→conflict 409→delete), single-user token mode.

### Task 9: Sync client

- `packages/core/sync/client.ts`: typed fetch client for the server API.
- `packages/cli`: `reglet login <url>` (email/password → pair; or `--token` single-user), `reglet sync` = pull-then-push:
  - pull: `GET /changes` since cursor → for each change, 3-way merge into local master (`base` = `.state/sync-base/<path>`, `ours` = local, `theirs` = remote) using `node-diff3` for `.md`/`.toml`/`.json` text; clean merge → write + update sync-base; conflict → write `<file>.conflict-<deviceName>.md` alongside, keep local, warn.
  - push: local files whose hash ≠ sync-base hash → PUT with baseRevision from sync state; on 409 → merge as above and retry once.
  - after any pull that changed master → `applyAll()`.
  - Sync scope: `rules/`, `skills/`, `mcp/servers.json`, `reglet.toml`. Never `.state/`.
- `reglet sync --watch` handled by daemon hook (wire the Task 7 no-op hook to push after apply, pull on interval 60s).
- Tests: two sandboxed clients against an in-process server — edit on A → sync → appears on B; concurrent divergent edits → conflict copy created; cursor persistence.
